# Mobile UI v0.1 Design

## Goal

Replace the desktop editor shell with a mobile-first web app where Today opens by default, quests complete in one tap, and users can inspect vertical skill trees and create Trees, quests, and skills from bottom sheets.

## Architecture

Keep workspace schema version 2, localStorage key, quest reward logic, status recalculation, and non-consuming unlock logic. `useSkillMap` remains the mutation boundary and gains atomic create/reset actions. `App` owns only navigation and overlay state; focused mobile and form components render pages and sheets. React Flow position data remains stored for compatibility but is ignored by the mobile tree renderer.

## Mobile Experience

- The fixed bottom navigation contains Today, Tree, and Add only.
- Today groups all quests by Tree, shows local-date progress, completes available quests immediately, and shows a brief CSS feedback toast.
- Today shows at most three available skills with direct unlock actions.
- Tree shows one selected Tree at a time. A pure depth calculation groups its skills from top to bottom using prerequisite relationships, independent of saved coordinates.
- Tapping a skill opens a bottom sheet with description, coin progress, prerequisites, status, unlock, and an edit entry point.
- Add opens an action sheet leading to focused Quest, Skill, or Tree forms. Skill creation accepts zero or one prerequisite in the UI while preserving the array-based data model.
- Settings contains Tree management and demo-data reset. Quest rows expose an explicit small menu for edit/delete.

## State and Persistence

Creation submits complete values atomically. Existing ids, categories, quests, skill nodes, edges, completion dates, balances, unlock states, and positions continue to round-trip through `skill-tree-workspace-v2`. Invalid persisted data continues to recover to demo data without crashing.

## Error Handling and Accessibility

Required fields disable submission until valid. Empty Tree coin names default to `<Tree name> Coin`. Removing a Tree keeps the existing cascade behavior and requires confirmation. Sheets use dialog semantics, backdrops close them, controls have accessible names, and interactive targets are at least 44px.

## Verification

Vitest and Testing Library cover Today quest completion, duplicate reward prevention, available skill unlock, vertical Tree selection and skill detail, and all three creation flows. Final verification runs `npm test -- --run` and `npm run build` before the requested commit and push.
